## Predeclared recipe

- Config: `configs/baseline.yaml`; run command below. Effective config, environment,
  code commit/dirty status, and source metadata are saved with artifacts.
- Encoder: torchvision ResNet-50, `ResNet50_Weights.IMAGENET1K_V2`, ImageNet-1K.
  Verify its downloaded SHA-256 and record the official URL. No scene-trained weights.
- Fitting/validation: committed IDs in `splits/`; no test inference in this run.
- Preprocessing: checkpoint transforms (resize shorter edge to 232, center crop
  224, RGB and ImageNet normalization), identically applied to fitting/validation.
- Encoder: no gradients; evaluation mode including BatchNorm. Extract each image
  once and cache features. No feature standardization, random crops, or flips.
- Head: one 2048-to-67 linear layer, trained on CPU with ordinary cross-entropy,
  AdamW, learning rate 0.001, weight decay 0.0001, batch size 128, seed 42.
- Duration: 30 epochs; retain best validation accuracy; ties keep earlier epoch.
- Feature extraction: auto device (CUDA, then Apple MPS, then CPU), batch size 32,
  zero loader workers for a simple portable first run. Log the actual device.

```bash
python -m src.train --config configs/baseline.yaml --run-id E001-seed42-v1
```

## Success and interpretation

Success means a complete reproducible baseline, not a promised target accuracy:
finite metrics, correct class/ID mapping, unchanged encoder, saved full checkpoint,
and validation predictions that can be regenerated by loading that checkpoint.
Inspect per-class confusion and training/validation curves after completion.

This first run cannot isolate architecture, optimization, and preprocessing
effects; it defines their reference combination. Center crops may lose room
context. Checkpoint selection on validation makes its selected score optimistic;
it is not an independent test result. More model choices require confirmation.

## Verification

Five automated pipeline checks passed, including split overlap rejection, explicit

Reloaded `best.pt` and re-evaluated the actual validation images on MPS: all 1,066

## Interpretation and next questions

- The frozen ImageNet representation establishes a usable reference. This run
  does not show whether another architecture or fine-tuning is better.
- Fitting accuracy approaches 100% while validation accuracy remains about 78%.
  This gap suggests generalization, representation, or preprocessing limits;
  it does not by itself identify which one, or prove fine-tuning will help.
- Best validation accuracy occurs at the last predeclared epoch. Do not claim
  convergence or silently extend this run; any extension needs a new run ID.
- Largest directed confusion: `concert_hall` to `auditorium` (5 images); the
  reverse accounts for 3. Other 3-image confusions include `library` to `bookstore`,
  `office` to `computerroom`, `deli` to `bakery`, `children_room` to `kindergarden`,
  `shoeshop` to `jewelleryshop`, and `airport_inside` to `subway`.
- Each class has only 15–17 validation examples. These counts identify candidates
  for validation-image review, not reliable evidence that a specific intervention
  will help. No semantic error tags or image-level causal explanation were assigned.

Next: review a reproducible validation-error sample; compare fine-tuning on the
same split and a context-preserving input policy in separate runs. Keep this
checkpoint as the reference and seek confirmation for small improvements.
